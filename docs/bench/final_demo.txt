======================================================================
ЧАСТЬ 1. Две версии одного договора
======================================================================
  строк без FINAL : 2   <- на диске лежат обе версии
  строк с FINAL   : 1   <- движок склеил их на лету, при чтении
  кусков на диске : 2   <- каждая вставка создала свой кусок
  без FINAL видно : [(Decimal('100000.00'), 200), (Decimal('250000.00'), 230)]
  с FINAL видно   : [(Decimal('250000.00'), 230)]   <- осталась версия с более свежей датой

  А теперь сумма без FINAL — главная ловушка:
  SELECT sum(...) без FINAL : 350000.00  <- сложились обе версии, цифра ложная
  SELECT sum(...) с FINAL   : 250000.00  <- верно

  Принудительное слияние (OPTIMIZE TABLE ... FINAL):
  строк без FINAL : 1   <- теперь дубль убран физически
  кусков на диске : 1

ЧАСТЬ 2. Чего стоит FINAL на 20 млн строк
======================================================================
  строк на диске        : 22 000 000
  строк логически       : 20 000 000
  разница (дубли)       : 2 000 000
  активных кусков       : 132

  запрос без FINAL      :     172 мс   (ответ неверный, дубли сложены)
  запрос с FINAL        :    1300 мс   (ответ верный)
  цена корректности     : x7.5
